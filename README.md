# nitpick-site

Marketing site for [nitpick](https://github.com/LVTD-LLC/nitpick), AI code review for AI agents.

Static [Astro](https://astro.build) site, served by nginx from a CapRover app. Live at https://nitpick.sh.

## Develop

```bash
npm install
npm run dev        # http://localhost:4321
npm run build      # astro check + astro build into dist/
npm run preview    # serve dist/ locally
```

Node 22 or newer.

## Recordings

The terminal recordings under `public/casts/` are real `nitpick` runs recorded with the asciinema CLI and played back with `asciinema-player`. `AGENTS.md` explains how to re-record one.

## Artwork

`public/art/hero.png` is the Open Graph image. It is generated by `scripts/dither.py` (needs Pillow); run `npm run art` only when it should change, and commit the result.

## Deploy

Every push to `main` runs `.github/workflows/deploy.yml`: build, tar `Dockerfile` + `nginx.conf` + `captain-definition` + `dist/`, and `caprover deploy` with an app token. The workflow waits until `https://nitpick.sh/deployment.txt` reports the deployed commit before marking the run successful. Three repository secrets are required:

| secret | value |
|---|---|
| `CAPROVER_URL` | CapRover origin, e.g. `https://captain.cr.lvtd.dev` |
| `CAPROVER_APP` | app name, `nitpick` |
| `CAPROVER_APP_TOKEN` | the app's deploy token from App Configs in CapRover |

To deploy by hand from a machine logged in with the `caprover` CLI:

```bash
npm run build && tar -czf /tmp/nitpick-site.tar.gz Dockerfile nginx.conf captain-definition dist
caprover deploy -n captain-01 -a nitpick -t /tmp/nitpick-site.tar.gz
```

## Review

Run `nitpick` from the repo root before opening a PR; `.nitpick.toml` carries the site-specific instructions. It needs `NITPICK_OPENROUTER_API_KEY` in the environment.

## IndexNow

`public/indexnow-key.txt` is the public ownership proof (not a private API credential).
The **IndexNow public URL changes** workflow runs after a successful **Deploy site**,
hourly at :41 UTC, or manually. It verifies the live `deployment.txt` revision and
ownership file, reads the public sitemap, and notifies IndexNow of current pages
on deployments plus changed/removed URLs since its last accepted checkpoint.
The 404 page and static assets are not submitted. Future public Astro pages are
included through the existing sitemap generator.

The Python standard-library script retries transient failures, batches at 10,000
URLs, and saves state only after every batch returns HTTP 200 or 202. A 202 means
key validation is pending; neither status guarantees indexing. Failed notifications
fail the separate workflow and retry on the next hourly run; deployment itself is
not marked failed by a search-engine outage.

GitHub Actions cache stores the checkpoint. Cache eviction causes a full current-URL
submission and loses historical removals. Pages created and deleted between successful
checks cannot be observed. Static content changes require deployment; each new revision
resubmits current pages even though the sitemap has no lastmod values.

```bash
python3 scripts/indexnow.py --site-url https://nitpick.sh --dry-run
python3 scripts/indexnow.py --site-url https://nitpick.sh --state indexnow-state.json --force
uv run --with pytest pytest scripts/test_indexnow.py
```

The second command sends real notifications. For routine operation, use the GitHub
workflow so its shared checkpoint remains authoritative. Protocol: https://www.indexnow.org/documentation

## PostHog analytics

Production builds use `PUBLIC_POSTHOG_PROJECT_TOKEN` (public, write-only project
key), `PUBLIC_POSTHOG_HOST=https://us.i.posthog.com`, and `PUBLIC_SITE_VERSION`.
GitHub Actions obtains the first two from repository secrets and uses its commit
SHA as the version. Never expose a personal PostHog API key. Local/dev builds and
non-production hostnames do not capture events.

[Nitpick project](https://us.posthog.com/project/654831): `$pageview`, `$pageleave`,
web vitals, `install_prompt_copied` (success boolean), `outbound_link_clicked`
(destination category), and `demo_played` (demo category). Exception capture
(PostHog error tracking) is disabled.
Pageviews supply web analytics; anonymous browser IDs support returning-visitor
analysis, not identifying names/emails. Website and CLI identities are separate.
No arbitrary DOM autocapture. Privacy controls, collection details and opt-out
are at `/privacy/`. Replay sampling is 20% in project settings, with text/input
masking and terminal demos blocked. Query/hash/unknown-path visits cannot replay.
Console/network payload recording is disabled. Browser errors are not captured.

`src/lib/analytics-policy.ts` is the allowlist/redaction boundary. Run
`node --experimental-strip-types --test scripts/analytics-policy.test.mjs` and
`npm run build`. For a real browser check, verify pageviews and copy clicks,
query/fragment redaction, DNT/GPC silence, persistent opt-out, error scrubbing,
and masked replay independently. Do not count SDK initialization as ingestion.
